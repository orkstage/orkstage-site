OrkStage creates Magalu Cloud resources with the
[MagaluCloud/mgc](https://search.opentofu.org/provider/magalucloud/mgc/latest) OpenTofu provider
(pinned to `~> 0.56.0`), one isolated state per resource, kept in an Object Storage bucket in your
own tenant. Health, existence checks and restarts use the regional REST API
(`https://api.magalu.cloud/<region>/`, header `X-API-Key`).

## What OrkStage creates

| Template resource | Capability | What gets created |
|---|---|---|
| `network` | `vpc` (default) | VPC, subnet pool, one IPv4 subnet and an internal security group |
| `compute.container-service` | `vm-docker` (default) | One VM per replica, with Docker installed and started by cloud init. The machine type is the smallest Balanced Value type that fits `cpu` and `memoryMiB`. Public services with more than one replica get a network load balancer on port 80. |
| `database.postgresql` | `dbaas-postgres` (default) | DBaaS instance, or a Multi AZ cluster for `zone-redundant`. Private address only. `secret_ref` is `mgc-db://<name>/<id>`. |
| `object-storage` | `object-storage` (default) | Private bucket with optional versioning |

There is no capability for `cache.redis` or `ingress`. Magalu Cloud has no managed Redis in the
provider. The network load balancer needs its targets at creation time, while OrkStage creates an
ingress before the services it routes to, so load balancing is built into `vm-docker` instead.

DBaaS does not return the master password, so when a resource on another provider needs the
database credentials, the adapter reads the password generated in that database's OpenTofu state
(in your bucket). Inside Magalu Cloud VMs, services receive the reference as
`<ID>_CREDENTIALS_REF`, not the value.

## Target configuration

| `config` field | Required | Meaning |
|---|---|---|
| `stateBucket` | yes | Object Storage bucket for OpenTofu state, in the region you deploy to |
| `sshKeyName` | no | Existing SSH key for service VMs. Without it, each service gets its own generated key; the private key stays in state and is never output. |

## Credential secret

```json
{
  "apiKey": "<Magalu Cloud API key>",
  "stateAccessKeyId": "<Object Storage key pair id>",
  "stateSecretAccessKey": "<Object Storage key pair secret>"
}
```

| Field | What it is |
|---|---|
| `apiKey` | API key created in ID Magalu (`id.magalu.com/api-keys`). Used by the OpenTofu provider and the REST API. |
| `stateAccessKeyId` | Object Storage key pair id of an API key with Object Storage access |
| `stateSecretAccessKey` | Object Storage key pair secret of the same key |

The key pair reads and writes OpenTofu state and is also given to the provider for bucket
operations. Secrets reach OpenTofu only as runner environment variables: `TF_VAR_mgc_api_key`,
`TF_VAR_mgc_key_pair_id` and `TF_VAR_mgc_key_pair_secret` (sensitive root variables, because the
provider takes these values from configuration only), plus `AWS_ACCESS_KEY_ID` and
`AWS_SECRET_ACCESS_KEY` for the S3 backend.

### Permissions

When creating the API key, grant read and write access to Network (VPC), Virtual Machines, SSH
Keys, DBaaS, Load Balancer and Object Storage. A target that deploys only some resource types can
leave the others out.

## Prepare state storage

Create the bucket before validating the target. OrkStage never creates it.

```sh
mgc object-storage buckets create acme-orkstage-tfstate
```

Create it in the target region, keep it private and turn on versioning in the console. State is
reached at `https://<region>.magaluobjects.com` with path style addressing. S3 lock files are off:
Magalu Object Storage support for conditional writes is not documented, and OrkStage already runs
one operation per resource at a time.

## Regions

Regions are `br-se1` and `br-ne1`.

## Actions for triggers

| Capability | Action | Parameters | Effect |
|---|---|---|---|
| `vm-docker` | `restart` | none | Reboots every virtual machine of the service |

## Known limits

- The network load balancer is TCP only (no path routing, no TLS termination) and is marked
  experimental by Magalu Cloud.
- No autoscaling: `replicas` is a fixed VM count. Changing the image or environment replaces the
  VMs.
- Images must be pullable without registry credentials.
- Environment values are written to VM user data.
- VMs get a public IPv4 each so they can pull images. Inbound traffic is limited to the service
  port (from anywhere for public services, from the VPC otherwise). `natGateway` is not applied,
  and `availabilityZones` does not create more subnets.
- DBaaS: `publicAccess` and same zone HA are not offered; backups are always on (1 to 35 days);
  the requested PostgreSQL version must be active in the region, or the module fails with the list
  of active versions.
- Object Storage: `publicAccess`, `tier` and `retentionDays` are not applied, and a bucket must be
  empty before it is destroyed.
- Magalu Cloud tags are tenant wide and authoritative per resource, so template tags are not
  applied.
- Running containers on Magalu Cloud Kubernetes is not supported.
