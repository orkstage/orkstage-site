Architecture decision records (ADRs) live in `docs/adr/` of the platform repository. Each summary
below links to the full record.

## 0001 Per resource placement through template slots

**Accepted.** Templates are shared across tenants, but each tenant has its own cloud accounts. So
the provider, account and region cannot live in the template.

Instead, a template declares **placement slots**, each with a list of allowed providers. Every
resource names a slot, and every instance binds each slot to `{ targetId, region }`. The same
template runs on one cloud or on several, depending only on the bindings. Networks bind only to
resources in the same slot.
[Read ADR 0001](https://github.com/orkstage/orkstage/blob/main/docs/adr/0001-placement-slots.md)

## 0002 Provider adapters, capability catalogs and simulation

**Accepted.** `CloudProviderAdapter` is the only way the platform touches a cloud. Its
`ensureResource` call converges a resource to the desired state, so a retry cannot create a
duplicate.

The mapping from a logical resource to a provider implementation is **data**: capability catalogs
that list features, regional gaps and static prices. A deterministic `mock` provider simulates
AWS, Azure or OCI with injectable failures, and the platform labels everything it simulates. One
shared contract test suite runs against every adapter.
[Read ADR 0002](https://github.com/orkstage/orkstage/blob/main/docs/adr/0002-adapters-and-simulation.md)

## 0003 Deployment workflow on BullMQ with persisted steps

**Accepted.** Temporal would add a cluster to operate. BullMQ reuses the Redis and Postgres that
the platform already requires.

A job carries only the deployment id. Steps are database rows, created when the deployment is
requested and updated before and after each action. Resuming a deployment means running the same
job again, which skips the phases that already finished. Temporal is worth another look if long
flows that wait on people, or very large fan out, appear.
[Read ADR 0003](https://github.com/orkstage/orkstage/blob/main/docs/adr/0003-workflow-engine.md)

## 0004 Tenancy, sessions and authorization

**Accepted.** All tenants share one database, and every row a tenant owns carries a `tenantId`.
Isolation works in four layers: the request principal, query scoping by membership, a CASL check
on the loaded record, and the audit log. A record from another tenant is reported as not found.

CASL rules are defined once. The API enforces them, and the console receives them only to decide
what to show. Sessions are opaque and stored on the server, not JWTs. OIDC providers are plain
configuration.
[Read ADR 0004](https://github.com/orkstage/orkstage/blob/main/docs/adr/0004-tenancy-and-authorization.md)

## 0005 OpenTofu execution and state

**Accepted.** Every `tofu` command runs in a throwaway container with a pinned image. Credentials
exist only in that container's environment.

Each resource has **its own state file** in S3, locked with `use_lockfile` and encrypted. This keeps
the platform's own DAG and isolates a failure to one resource. State holds no secrets: passwords
come from ephemeral resources and travel through write only attributes. The same code serves real
AWS and MiniStack.
[Read ADR 0005](https://github.com/orkstage/orkstage/blob/main/docs/adr/0005-opentofu-state.md)

## 0006 Toolchain choices

**Accepted.**

- pnpm workspaces without Turborepo, because development machines block native binaries from
  `node_modules`.
- TypeScript 7.
- Prisma 7.10, not the 8.0 release candidate.
- Zod 4, shared by request validation, the OpenAPI document and console forms.
- ESM everywhere.

[Read ADR 0006](https://github.com/orkstage/orkstage/blob/main/docs/adr/0006-toolchain.md)

## 0007 Profiles, tenant limits and template tags instead of plans

**Accepted.**

Plans and their entitlements are gone. Each tenant has optional limits that platform owners and
admins set, and feature flags decide whether its templates may use several clouds, several
regions, autoscaling and custom domains. Templates carry free form tags instead of a list of plans
and a size profile (`spec.plans` and `metadata.profile` are ignored with a warning for one
release). Named profiles of accounts and regions per environment replace the default cloud
targets: new instances bind the slots they leave unbound from a profile.
[Read ADR 0007](https://github.com/orkstage/orkstage/blob/main/docs/adr/0007-profiles-limits-tags.md)

## 0008 A real shared network per cloud target for sandbox instances

**Accepted, not built yet.**

Templates that ask for `network.strategy: shared` will use one platform owned network per cloud
target and region instead of a network and NAT gateway per instance. Isolation comes from per
instance security groups that deny by default; production instances can never use it.
[Read ADR 0008](https://github.com/orkstage/orkstage/blob/main/docs/adr/0008-shared-sandbox-network.md)

## 0009 Provider actions from one catalog

**Accepted.**

Operations people run on live resources (scale, restart, snapshot, invalidate a cache) come from
one catalog with parameters, risk and the role each needs. Adapters declare which ones they
support, and triggers and future agents use the same vocabulary.
[Read ADR 0009](https://github.com/orkstage/orkstage/blob/main/docs/adr/0009-provider-actions.md)

## 0010 Prices from provider pricing APIs, with bundled tables per region

**Accepted.**

Cost estimates use the provider's pricing API when the target can read it, and a bundled price table
per region otherwise. Each line says which source it used and whether a price was derived.
[Read ADR 0010](https://github.com/orkstage/orkstage/blob/main/docs/adr/0010-regional-pricing.md)

## 0011 Authentication, single sign on and API keys

**Accepted.**

No passwords: OIDC providers and GitHub, accounts linked by verified email only, opaque server side
sessions with an idle timeout, and API keys that act for their creator with a role, scopes and an
expiry. SAML, SCIM and MFA policies are Enterprise features.
[Read ADR 0011](https://github.com/orkstage/orkstage/blob/main/docs/adr/0011-authentication-and-sso.md)

## 0012 Observability of the control plane

**Accepted.**

JSON logs with a correlation id from the request to the OpenTofu run, OpenTelemetry traces and
metrics when an OTLP endpoint is set, health endpoints for orchestrators, and an audit log that
does not depend on the log pipeline.
[Read ADR 0012](https://github.com/orkstage/orkstage/blob/main/docs/adr/0012-observability.md)

## 0013 Health roll up, incidents and status pages

**Accepted.**

Resource health rolls up by criticality into customer facing components; rules open one incident
per failure and resolve it on recovery; status pages are private, for members or public, and show
names and states only.
[Read ADR 0013](https://github.com/orkstage/orkstage/blob/main/docs/adr/0013-status-pages-and-incidents.md)

## 0014 Sandbox instances without plans

**Accepted.**

A sandbox is a non production template, the `sandbox` environment and tenant limits, not a plan.
Non production templates never reach production.
[Read ADR 0014](https://github.com/orkstage/orkstage/blob/main/docs/adr/0014-sandbox-instances.md)

## 0015 AI mini agents attached to templates

**Proposed, not built.**

Small, read only agents a template opts into, run on the plan and after the deployment with the
tenant's own model provider. They return findings and suggest catalog actions; people decide.
[Read ADR 0015](https://github.com/orkstage/orkstage/blob/main/docs/adr/0015-ai-mini-agents.md)

## 0016 OpenTofu runs on Docker, ECS or Kubernetes

**Accepted.**

The worker starts OpenTofu through an executor: containers on its Docker host, ECS tasks or
Kubernetes Jobs, the last two without the Docker socket. Credentials reach the runner through a
file it deletes on read, never through a task or Job definition.
[Read ADR 0016](https://github.com/orkstage/orkstage/blob/main/docs/adr/0016-runner-executors.md)

## Writing a new ADR

Copy the structure of an existing record: **Status**, **Context**, **Decision** and
**Consequences**. Give it the next number and keep it short. To change an accepted decision, write
a new ADR that supersedes it instead of editing the old one.
