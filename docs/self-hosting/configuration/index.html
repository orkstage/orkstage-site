Configuration reference

Every OrkStage environment variable with its type, default and effect, from core settings and OIDC to the OpenTofu runner, email, secrets and licensing.

The API and the worker read the same typed configuration (packages/runtime/src/config.ts). They refuse to start on invalid values and list every problem they find. In local development they load a .env file from the repository root (cp .env.example .env). Real environments inject the variables.

Booleans accept true, false, 1 or 0.

Single sign on (OIDC)

A provider is enabled when all three OIDC_<KEY>_* variables are set and the issuer contains no <placeholder>. The keys ENTRA, GOOGLE and GITLAB get display names. Any other key is shown as written. Register this redirect URI at the provider:

The flow uses the authorization code grant with PKCE (S256) and verifies state and nonce. Accounts are linked only through an email address the provider has verified.

Microsoft Entra ID is the reference provider. Google and GitLab work through configuration alone but have had less testing. GitHub does not speak OIDC for sign in, so it needs an OAuth adapter, which does not exist yet.

Rate limits behind proxies

Rate limit counters live in Redis, so they hold across every API instance. Signed in requests are counted per session or API key. Sign in routes are counted per client address, which is only as trustworthy as the proxy that records it: put a load balancer or reverse proxy that appends the client address to X-Forwarded-For (an AWS ALB, nginx with proxy_add_x_forwarded_for) in front of the console, and leave TRUST_PROXY_HOPS at 1. The console's own proxy passes an incoming X-Forwarded-For through unchanged, so without such a proxy a client can pick the address the API sees for sign in limits. If the API is exposed directly, set TRUST_PROXY_HOPS=0.

Seed

The seed runs after migrations (the migrate service, or pnpm db:seed). It is idempotent.

VariableDefaultDescription
PLATFORM_OWNER_EMAILnoneCreates this user as the platform owner, or gives an existing user that role. There is no development sign in in production, so this is how the first administrator is created: they sign in with SSO using this email, which the provider must report as verified. Without it, a production seed warns that nobody can administer the platform.
ORGANIZATION_NAMEOrganizationName of the organization created on the first run, when none exists.
SEED_DEMO_DATAtrue, except with NODE_ENV=productionAdds the demo: simulated cloud targets, sample images, the Acme and Globex tenants and their users. Without it, the seed writes only plans, built in and marketplace templates, the organization and the platform owner.

Production safety checks

With NODE_ENV=production, startup fails when any of these is true:

  • AUTH_DEV_LOGIN_ENABLED is true.
  • ENCRYPTION_KEY is missing.
  • WEBHOOK_ALLOW_PRIVATE is true.
  • SESSION_SECRET still starts with change-me.
