Webhooks

Receive signed OrkStage events over HTTPS. Event types, payload, signature checks in Node.js, Python and Go, retries, testing and redelivery.

OrkStage sends events to your HTTPS endpoints as JSON POST requests signed with HMAC-SHA256. Use them to post to chat, open tickets, start pipelines or feed your incident tools.

Creating an endpoint

In the console, open Integrations, then Webhooks, then New webhook. Through the API, use a session or a key with webhooks:manage:

format is ORKSTAGE by default. SLACK and TEAMS send a chat message to an incoming webhook of that service instead of the signed JSON event, see notifications.

The response contains { webhook, secret }. You see the signing secret (whsec_…) once. The server stores it encrypted with ENCRYPTION_KEY. To rotate it, call POST /webhooks/:id/rotate-secret, which returns the new secret.

OrkStage checks the URL when you create the endpoint and again before every delivery, because DNS can change:

  • The URL must use https:// and must not contain credentials.
  • The host must not resolve to a private, loopback, link local or multicast address.
  • Redirects are not followed, and each request times out after 10 seconds.

For local development, WEBHOOK_ALLOW_PRIVATE=true also accepts http:// URLs and private addresses. The API refuses to start with this setting in production.

The request

OrkStage-Delivery is unique per delivery and stays the same across retries. A manual redelivery is a new delivery with a new OrkStage-Delivery value, but its body keeps the original id. To drop duplicates, use the body id, which covers both retries and redeliveries.

Verifying the signature

  1. Read the raw request body, before any JSON parsing.
  2. Split the header on , and = to get t and v1.
  3. Reject the request if t is more than 300 seconds away from your clock. This protects against replays.
  4. Compute HMAC-SHA256(secret, t + "." + rawBody) as lowercase hex and compare it with v1 in constant time.
  5. Answer with a 2xx status quickly, and do the work in the background.

The platform uses the same algorithm in verifyWebhook (packages/runtime/src/webhooks.ts).

Retries and failures

SuccessAny 2xx response within 10 seconds. OrkStage ignores the response body.
Retry scheduleAfter a network error or a status outside 2xx, OrkStage retries after 1 minute, 5 minutes, 30 minutes, 2 hours and 6 hours. Then the delivery is FAILED.
Automatic disablingAfter 20 failed deliveries in a row, OrkStage disables the endpoint and records a reason. Turn it back on with PATCH /webhooks/:id { "enabled": true }, which also resets the failure count.

Testing and redelivery

EndpointWhat it does
POST /webhooks/:id/testSends a ping at once and returns the delivery result.
GET /webhooks/:id/deliveriesLists the last 50 deliveries with status, attempts, response status and error.
POST /webhooks/:id/deliveries/:deliveryId/redeliverCreates a new delivery with the same payload and answers 202. The worker sends it on its next pass.
PATCH /webhooks/:idChanges url, description, events or enabled.
DELETE /webhooks/:idRemoves the endpoint.

In the console, open Integrations, then Webhooks. The Deliveries button of an endpoint lists its recent deliveries, each with a Redeliver button.
