REST API overview

How the OrkStage Control API v1 works. Base path, API keys and sessions, the CSRF header, errors, pagination, correlation ids, idempotency and rate limits.

The Control API is the only way into the platform, and the console uses it too. The base path is /api/v1. A running API serves an OpenAPI UI at /api/docs and the OpenAPI document at /api/docs-json. The API reference in these docs is generated from that document.

Authentication

Send an API key as a bearer token. You need no cookie and no CSRF header.

A key reaches only the endpoints that declare a scope. Endpoints without a scope, such as API key management, answer 403 API_KEY_NOT_ALLOWED to a key.

GET /me returns the caller, their memberships and the authorization rules. When you call it with an API key, it also returns apiKey: { id, name, prefix, scopes }.

Correlation ids

Send x-correlation-id to tie your logs to ours. Every response carries x-correlation-id and x-request-id. The correlation id follows the request into deployments, OpenTofu runs, audit events and webhook deliveries, so quote it when you report a problem.

Pagination

Every list endpoint uses cursors:

Pass nextCursor as cursor until it is null. limit goes up to 100. sort names a field the list allows, such as name or createdAt, with a leading - for descending order; any other field is refused with 400 INVALID_SORT. Without sort, instances, deployments, incidents, API keys and webhooks come newest first, tenants and templates by name, and cloud targets oldest first.

Idempotency

Deployments are keyed by tenant, instance and a hash of the desired state. While an instance has an operation in progress, further deploy or destroy requests get 409 INSTANCE_BUSY, and the worker never recreates resources that have already converged.

Any POST, PUT, PATCH or DELETE may also carry an Idempotency-Key header (8 to 200 letters, digits or -, _, ., :), so a retry after a timeout or a dropped connection does the work only once:

  • The first successful response is kept for 24 hours, per caller (a person or an API key). A retry of the same request gets the same response again, with the header idempotent-replayed: true.
  • The same key for a different request is refused with 422 IDEMPOTENCY_KEY_REUSED.
  • A retry while the first request still runs gets 409 IDEMPOTENCY_IN_PROGRESS; retry later.
  • A request that failed keeps nothing, so retrying it runs it again.

The console sends a key on deploys, destroys, upgrades, instance creation, trigger runs and invitations, and the ork CLI on every change it makes.

Tenancy

Reads of tenant records are filtered by the caller's memberships, and every write is checked against the record loaded from the database. The API never trusts a tenantId in a request on its own.

Rate limits

Limits are counted per client IP address and per endpoint, over a 60 second window. An endpoint accepts 600 requests per minute from one client unless it has a lower limit:

EndpointRequests per minute
Development login10
OIDC login and callback20 each
Deploy10
Destroy5
Cloud target validation10
Template version publishing10
API key creation20
Import creation20
Webhook creation20
Webhook test10

GET /healthz and GET /readyz have no limit. A 429 response means wait and retry with backoff.
