Creating an instance

Create an OrkStage instance with the six step wizard. Pick the tenant and template, bind each slot to a target and region, then set variables.

A new instance starts as a DRAFT, and nothing is provisioned until you deploy it. Open Instances, then New instance. Creating an instance needs a platform owner or admin role, or the customer owner or admin role in the tenant.

The six wizard steps

Tenant

Choose the customer that owns the instance. The tenant's plan decides which templates and placements are allowed, and the instance's cost is attributed to that tenant.

Template

Pick a template and one of its published versions. Published versions never change, and drafts cannot be used. Templates marked nonProduction show a warning. The non-production-template policy fails if you use one for a production instance.

Placement

Bind every placement slot of the template to a cloud target and a region. Slots can use different clouds. With multicloud-reference, for example, primary can run on AWS, data on Azure and storage on OCI. The list offers only targets whose provider the slot accepts, and only the regions each target allows.

Simulated targets (the mock provider) carry a simulated label. Use them to rehearse a topology before you connect real accounts.

Variables

Templates expose a few typed variables, for example apiReplicas or databaseSize. The form starts with the default values. The browser checks ranges and allowed values, and the API checks them again.

Name and environment

Give the instance a name and a slug. The slug is lowercase and goes into physical resource names such as ork-acme-staging-api. Then choose the environment: production, staging, development or sandbox. Production instances get stricter policies (backups are required) and an approval step for high risk changes.

Review and create

Check the summary and create the draft. The console opens the instance page, where the Plan & cost tab previews what a deployment would do.
