Release process

The CI checks that run on OrkStage today, and the planned release flow for images, packages, signed CLI binaries, modules and this site.

No tagged releases yet

OrkStage is developed on main and has not published a versioned release. This page lists the checks that run today and the release flow being prepared.

What CI checks today

Repository partChecks
Platform (.github/workflows/ci.yml)pnpm install --frozen-lockfile, build, type check and tests. Migrations apply cleanly on Postgres, and the seed runs twice to prove it is idempotent. pnpm audit --audit-level high reports vulnerable dependencies but does not fail the build yet.
CLI (cli/.github/workflows/ci.yml)cargo fmt, clippy -D warnings and tests on Linux, macOS and Windows. The committed WASM package must match a fresh build and pass a smoke test. Release builds run for 8 targets. On tags, and only when the signing secrets are configured, Windows binaries get Authenticode signatures and macOS binaries get Developer ID signing and notarization.

Planned release flow

  1. Versioning. Each repository uses semantic versions. A breaking API change gets a new /api/v2 route group. The template schema has its own version (platform/v1).
  2. Platform. A tag builds and publishes ghcr.io/orkstage/platform:<version> and the shared packages (@orkstage/contracts, /authorization, /templates and /domain). The exported OpenAPI document is attached to the release.
  3. Console. A tag publishes ghcr.io/orkstage/console:<version>, pinned to a compatible range of the contracts package.
  4. CLI. A tag publishes signed ork binaries for Linux (glibc and musl), macOS and Windows on x86_64 and arm64, then @orkstage/scan on npm, then manifests for Homebrew, Scoop and winget.
  5. Modules. Git tags vX.Y.Z publish ghcr.io/orkstage/tofu-runner:<tag>. The platform pins the runner tag, so a module change is always an explicit upgrade.
  6. Compatibility matrix. orkstage-dev/COMPATIBILITY.md lists the combination of versions that was tested together. Its CI runs the end to end suite against that combination.
  7. Site. This site refreshes the API reference from the release's OpenAPI file and deploys to S3 and CloudFront.

Changelog and security fixes

Each repository will keep a changelog per release. Security fixes ship as patch versions. The plan is for Enterprise customers to receive security advisories before public disclosure.
