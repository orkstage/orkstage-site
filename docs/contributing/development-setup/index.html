Development setup

Work on OrkStage in its development workspace with Node.js 24, pnpm 12 and Docker, from first checkout to pull request, plus the Rust CLI and this site.

Requirements

  • Git, with access to the orkstage organization.
  • Node.js 24 or later and pnpm 12. Run corepack enable to get the pnpm version pinned in package.json.
  • Docker, for Postgres, Redis, Mailpit, MiniStack and the OpenTofu runner containers.
  • Nothing else for the CLI: its Rust builds run in a container.

The workspace

OrkStage lives in several repositories. The orkstage-dev workspace checks them out as git submodules and wires them together, so you can change the control plane and the console in one place.

How it fits together:

  • orkstage/ (the core) is a normal clone with its own pnpm workspace and lockfile. Inside it, every command works as in a standalone checkout. It does not use Turborepo: pnpm -r already runs scripts in dependency order (see ADR 0006). All code is ESM TypeScript 7 with module: NodeNext.
  • The workspace root holds the console and the scan engine package. The console's @orkstage/* dependencies point to orkstage/packages through pnpm overrides, so a change in a shared package reaches the console after pnpm core:build, with nothing to publish.
Command (workspace root)What it does
pnpm bootstrapInitializes the submodules, installs the git hooks, installs and builds everything.
pnpm syncMoves every submodule to the latest main and reinstalls.
pnpm statusShows the branch and changes of every submodule.
pnpm build / pnpm test / pnpm typecheckRuns the core, then the console.
pnpm db:migrateCreates a migration after you edit orkstage/packages/database/prisma/schema.prisma.
pnpm db:deploy / pnpm db:seedApplies migrations, or loads demo data. The seed is idempotent.
pnpm local:awsStarts MiniStack, the local AWS emulator.
pnpm platform:up / platform:logs / platform:downBuilds and runs the full stack in Docker Compose.

Inside orkstage/, MINISTACK_E2E=1 pnpm --filter @orkstage/cloud-aws test runs the adapter contract tests against MiniStack, and pnpm format or pnpm format:check runs Prettier.

Pull requests

Every change reaches main through a pull request in the repository that owns the code:

  1. Run pnpm sync so every submodule is on the latest main.
  2. In the submodule you are changing, create a branch, commit and push it, then open a pull request. CI runs on the pull request.
  3. Merge with a squash merge once CI is green. Merged branches are deleted automatically.
  4. When a set of versions works together, commit the new submodule pins in orkstage-dev, also through a pull request.

The workspace pre-push hook refuses direct pushes to main from your machine. On the server, rulesets require pull requests and green CI on main once the GitHub plan allows them for private repositories.

Supply chain settings

  • Only the packages listed under allowBuilds in pnpm-workspace.yaml may run build scripts. Telemetry that runs at install time is denied.
  • pnpm's minimum release age keeps very recent releases out. If a dependency is too new, pin the newest older version that qualifies instead of adding an exemption.

The CLI and scan engine (Rust)

Development machines may block unsigned native executables. So the CLI is built, tested and linted in containers:

On Windows, Git Bash needs $(pwd -W) and MSYS_NO_PATHCONV=1. PowerShell needs ${PWD}.

Snapshot tests use insta. Fixtures live in crates/orkstage-scan/tests/fixtures/<kind>/<project>/.

OpenTofu also runs only in containers, started by the worker's runner. You do not need to install it.

This site

The website and docs live in the orkstage-site repository (orkstage-site/ in the workspace). The site is its own pnpm workspace:

Docs are MDX files in content/docs/. Each section folder has a meta.json with "root": true, which turns the section into a sidebar tab. The API reference is generated from openapi/orkstage.json.
