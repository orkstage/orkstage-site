Free tier accounts

Prove OrkStage against real AWS, Azure and Oracle Cloud accounts on their free offers, with the Portable starter template, a budget alert and a clean teardown.

This guide deploys a small environment into real accounts that cost little or nothing: the Portable starter template, which is a network, one public web service and the provider's ingress. It has no database, registry or DNS record, so every infrastructure provider can run it and it fits the free offers below.

Offers change

The terms below were checked on October 17, 2026 against the official pages linked next to each one. Read them again before you sign up, set a budget alert first, and destroy the instance when you are done.

Before you start

  1. OrkStage running. The local stack is enough: follow the first steps of Choose a setup and sign in as admin@example.local.
  2. Secrets in .env.local. Targets reference their secrets as env://NAME. On the local stack, put those lines in .env.local at the workspace root (Git ignores it), then run docker compose restart api worker.
  3. The cloud's command line tool, signed in to the new account: the AWS CLI, the Azure CLI or the OCI CLI.
  4. A budget alert on the account, before any deployment. Each section says where.

AWS

AWS account and budget

Sign up at aws.amazon.com/free on the Free plan. In Billing and Cost Management > Budgets, create a monthly cost budget of $10 with an email alert. Setting up a budget is also one of the tasks that earn more credits.

OrkStage identity in AWS

On the local stack, OrkStage uses one of your AWS CLI profiles. Create an IAM user (or an IAM Identity Center user) for it, attach the policy from infra/aws/orkstage-control-plane-policy.json, configure a profile named orkstage, then restart the stack with it:

Connect AWS in the wizard

In the console, Cloud targets > Connect a cloud > Amazon Web Services. Type the account id, the identity ARN and the region (us-east-1 keeps the cost estimates exact). The wizard fills in the commands for the deployment role, the state bucket and the external id. Run them, put the external id line in .env.local, restart the API and worker, then continue: the wizard registers the target and validates it.

From a terminal instead:

Deploy the portable starter on AWS

When validation passes, click Deploy the portable starter. Choose a tenant, bind the slot to the new target, set the environment to development, review the plan and deploy. The service answers on the load balancer address shown on the instance page.

Clean up AWS

Destroy the instance. Leaving it running costs about $1.20 a day from the credits: the load balancer, the Fargate task and its public IPv4 address, which AWS charges whether it is used or not.

Azure

Azure account and budget

Sign up at azure.microsoft.com/free. In Cost Management > Budgets, create a monthly budget of $10 with an alert. A new subscription can take up to 48 hours before budgets are available, and budgets alert without stopping anything.

Turn on Azure

Azure is off by default. In the wizard's first step, choose Microsoft Azure and click Turn it on for the platform (or Settings > Feature flags, PROVIDER_AZURE).

Connect Azure in the wizard

Type the subscription id, a location (for example eastus) and a name for the state storage account. The wizard fills in the commands for the service principal and the state storage. Run them, keep the appId, password and tenant the first command prints, and put the client secret in .env.local:

Restart the API and worker, type tenantId and clientId in the details step, then register and validate.

Deploy the portable starter on Azure

As on AWS: choose a tenant, bind the slot to the Azure target, environment development, review and deploy. The web service runs on Container Apps and answers on its built in ingress.

Clean up Azure

Destroy the instance. The Log Analytics workspace that Container Apps need has a small ingestion cost; the state storage account stays until you delete its resource group.

Oracle Cloud

OCI account and budget

Sign up at oracle.com/cloud/free and choose the home region carefully: Always Free resources live only there. In Billing > Budgets, create a budget with an email alert.

Turn on OCI

OCI is off by default. In the wizard's first step, choose Oracle Cloud Infrastructure and click Turn it on for the platform (or Settings > Feature flags, PROVIDER_OCI).

Connect OCI in the wizard

Type the region and the compartment OCID. The wizard gives you the commands for the API signing key, the policies for the group of its user, the state bucket and its customer secret key, and a one line command that writes the credential to .env.local. Restart the API and worker, type the tenancy and user OCIDs, the fingerprint and the namespace in the details step, then register and validate.

Deploy the portable starter on OCI

As on AWS, with the slot bound to the OCI target and environment development. The web service runs on Container Instances (1 OCPU minimum) behind the Always Free flexible load balancer.

Clean up OCI

Destroy the instance. Container Instances use the trial credit; when the trial ends, OCI deletes paid resources, and an empty state bucket stays within the Always Free storage.

When something fails

The validation step names the check that failed and why. The usual causes:

MessageFix
Secret ORKSTAGE_... is not setThe line is missing from .env.local, or the API and worker were not restarted after adding it
OrkStage has no AWS identity of its ownStart the stack with AWS_PROFILE=<profile> pnpm platform:aws-real
Access denied assuming the deployment roleThe role stack's ControlPlanePrincipalArn or external id does not match
State bucket or container missingRun the state step of the wizard again for that region
A quota error during the deploymentNew accounts have low quotas; pick another region or ask the provider to raise it
